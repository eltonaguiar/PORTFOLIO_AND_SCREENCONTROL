G2 case study why the “headful fixes it” advice failed

The test and the result
ModeHTTPUser-Agentwebdriver
headless403HeadlessChrome/153…false
headful (Xvfb)403Chrome/153…false

Removing the “Headless” token changed nothing — the block is IP/reputation-side. robots.txt does not disallow /; it restricts query-string variants and sets Crawl-delay: 1. The real constraint is the site's Terms of Service.

We did not build CAPTCHA solving or proxy rotation. For G2 at scale, use their official API/partnership or a licensed data vendor.

Practices that survived contact
  • Prefer JSON. Availability APIs and embedded Next.js data outlive HTML changes and often bypass the bouncer.
  • Cache and throttle. One page every several seconds; never re-fetch what you already stored.
  • Record provenance. Keep status code, timestamp and byte count with every row.
  • Respect robots and ToS. A tool working is not permission.

Trading strategies & paper trading 03

ELI5
A backtest is a time machine that is easy to cheat. This section asks not just “did the rule make money?” but “is that number real, or did we try a thousand rules and keep the luckiest?”
The harness and the hypotheses
  • Section index and progress.
  • Harness certification — tests before trusting a result.
  • Fabrication checklist — how a backtest lies.
  • Pre-registered hypotheses and fold-sensitivity studies (see the folder).
Anti-overfitting rules used
  • Multiple-testing corrections (deflated Sharpe) and permutation/positive controls.
  • Walk-forward and fold stability; a single good window is not evidence.
  • Costs, slippage and funding charged before any verdict.
  • Paper/forward rows timestamped before outcomes; reconstructed rows are labelled.

A “pass” here is research-grade. It is not a promise of live profit.

Limits & honesty read me

ELI5
If a number here cannot be reproduced, it does not count. These are the known ways this project can fool itself.
What to distrust
  • Headline backtests. A high Sharpe is cheap when many rules were tried; demand the trial count.
  • Cash-heavy “wins”. Sitting in cash can look safe while losing to the benchmark. Compare on active return.
  • Single-path forecasts. Stochastic models vary run to run; seed them and report medians.
  • “Forward” data recorded after the fact. A row created after its entry is a reconstruction, not a forecast.
  • Tool capability ≠ site access. A browser passing one check can fail the next; a 200 can still be a challenge page.
  • ToS compliance. Working code is not permission to scrape.
Where the raw evidence lives
  • Best Buy / Walmart success artifacts (JSON + scripts).
  • JA3 stability + UA cross-check.
  • ghcopilot evaluation · zoocode evaluation.
